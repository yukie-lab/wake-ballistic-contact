# Phase 0 メモ 4 — データ層設計(スキーマ v0)

> 2026-08-14 / PHASES.md Phase 0 作業項目4 / 出口条件「データ層スキーマ確定(差替テスト)」対応
> 実装: `src/wake_data/`(schema / catalog / selection)+ `src/tests/test_swap.py`

## 1. 設計

3層構造。上位層(到来統計・排除地図)は抽象インターフェースのみに依存する。

```
CatalogProvider.load() → StarCatalog(スキーマ v0 準拠 + release/epoch/frame メタ)
SelectionFunction.completeness(G, BP-RP, ra, dec) → [0,1]
                 .weights(...) → 逆確率重み(floor 未満は NaN = 判定不能域)
```

- **カタログ差替**(憲法第8条1項): DR3 → DR4 の違いは Provider 内部の写像で吸収。
  スキーマ自体は不変。`DummyCatalogProvider` の v1(DR3想定)/v2(DR4想定)で差替を常時テスト。
- **選択関数も同格の差替部品**(第8条2項): `SelectionFunction` は Provider と同じ階級。
  具体モデルの選定は**フォーク3裁定待ち**(メモ3参照)— ここでは枠のみ固定。
- **判定不能の配管**(第5条6項の先取り): 完備性が floor (10⁻³) 未満の領域は補正せず
  NaN を返し、上位層が「判定不能」として別扱いする。偽の補正で埋めない。

## 2. スキーマ v0 の要点

- Gaia アーキタイプ準拠: astrometry 5パラメータ + RV、誤差、5×5 相関の上三角10個
  (誤差 MC の全共分散サンプリングに必要 — 第8条3項)。
- 測光 (G, BP-RP) は必須列。選択関数の引数になるため。
- **`rv_provenance` 列**(0=Gaia RVS / 1=外部サーベイ / 2=事前分布サンプル / -1=欠損):
  RV の出所を強制明示。フォーク3でどの補完戦略を採っても、完備性補正の対象集合を
  出所別に分離できる。RV=NaN と出所フラグの不整合はスキーマ検証で拒否される。

## 3. 差替テスト結果(2026-08-14 実行、全項目 PASS)

1. カタログ差替: 同一パイプラインコードで dummy-v1 → dummy-v2(6D星 1197→2244)
2. 選択関数差替: unity → 等級シグモイドで補正カウントが応答(1197 → 1609)
3. スキーマ違反(必須列欠落)を Provider 境界で検出
4. RV欠損×出所フラグの不整合を検出
