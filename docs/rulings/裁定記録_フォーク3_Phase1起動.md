## 第一部 フォーク3 裁定(Phase 0 出口条件)

### 裁定1 — 補正方式: 案A を主経路として採用
- IPW(Horvitz–Thompson 型)+ 判定不能明示。案B(前向きモデル)は不採用(モデル依存性が
  「実測カタログ主義」の新規性を薄めるため)。案C(外部 RV 併合)は任意オプションとして保留。
- **追加区画 A′(憲法第4条5項に新設)**: 晩期 M 型の到来「率」は、RV なしでも
  接線速度の脱射影(等方性仮定)× GCNS 体積完備数密度でバウンド推定可能。
  排除地図は率だけを必要とし個別イベント同定を必要としないため、この推定は
  イベントカタログを汚さずに最大母集団の沈黙を防ぐ。Phase 3 拡張区画・v1 必須ではない。
  地図併記時は仮定(等方性)を明示すること。

### 裁定2 — 晩期 M「判定不能」明示: 承認(条件付き)
- 承認条件: 条件付き確率文の冒頭に対象母集団を必ず明記する
  (例: 「FGK+早中期 M の補正後到来率の下で」)。憲法第7条3項として明文化済み。

### 裁定3 — s_floor: 現行 10⁻³ を棄却、暫定 0.05 に引き上げ(二段裁定)
- 理由: floor は数値下限ではなく**分散管理パラメータ**である。10⁻³ は重み 1000 を許容し、
  S≈10⁻³ の星が一件検出されただけで補正後率が単一イベントに支配される
  (HT 推定量の分散は重みの二乗で膨張)。
- 暫定値 0.05(最大重み 20)。**最終値は検証計画1の注入回収テストで
  バイアス–分散曲線を引いてから固定する**(第二段の裁定として前田さんに上げる)。
- 実装対応: `SelectionFunction.weights()` の floor 定数を 0.05 に変更し、
  floor をコンフィグ化(バイアス–分散スキャンで振れるように)。

### 裁定4 — 検証計画: 承認(要件1点追加)
- 注入回収テストのダミー選択関数に、等級シグモイドに加えて
  **HEALPix 依存の斑状選択関数(スキャン則パターン模擬)**を追加すること。
  空間構造は IPW の偽陰性バイアスの主因であり、等級依存だけでは試験にならない。
- 既知アンカー照合・DR2→DR3 整合(BJ18b 完備性 ~0.14 再現)・DR4 差替リハーサルは原案承認。

### 裁定5 — DR4 タイミング: v1 は DR3 で固める。DR4 は v1.1 差替再実行として分離
- 理由: (i) 公開日 2026-12-02 と Phase 2 の近接によるスケジュール従属の回避、
  (ii) 公開直後は選択関数側(gaiaunlimited 等)の DR4 対応が遅れるのが通例で、
  カタログのみ差し替えて補正が旧世代のままだと憲法第8条2項違反、
  (iii) 「DR3 で v1 → DR4 で差替再実行」の実演自体が差替設計の強さの証明になり、
  査読の「なぜ DR4 でないのか」への回答は差替リハーサル(検証計画4)で立つ。
- 帰結: Phase 2 以降のスケジュールは DR4 公開日に従属させないこと。

### スキーマ v1 の確定(裁定に伴う従属決定)
- 裁定1・3 に基づき v0 → v1 の追加列を確定してよい:
  RVS 有効温度範囲フラグ、健全性フラグ(検疫用)、および floor 判定の根拠列
  (S 値のキャッシュ)。列追加のみ・後方互換の原則(メモ4)を維持。
- これにより Phase 0 出口条件「データ層スキーマ確定」を ✅ 化してよい。

## 第三部 Phase 1 起動指示

### 冒頭裁定(実装開始前に材料を裁定に上げる。メモ2 §7 の5点)
1. **ポテンシャル2種**: 推奨案(MWPotential2014 + McMillan17、G3 再現時のみ BJ 型併用)で
   裁定に上げる。異論材料がなければ推奨のまま承認見込み。
2. **G3 合格帯**: メモ2 §6 の表を基礎に、以下の方針で最終案を整形して上げる:
   - G3-1 は固定入力再現テスト(憲法第6条 G3-1、1.1 で明文化済み)。
     厳格帯は DR3 系(−79.9 kyr / 0.33 pc)で固定、Mamajek15 系は緩和帯へ。
   - G3-3 は厳格=BJ+18 同一手法・同一入力再現、緩和帯 6–25 /Myr(桁の防護柵)。
     公刊間緊張(19.7 vs 10.6)の科学的裁定は Phase 2 の結果で行い、G3 では行わない
     (憲法第6条 G3-6)。
3. **個別ホライズン閾値 d_threshold**: 候補(接近半径 R の 1倍 / 0.5倍)の感度を
   小規模カタログで予備測定してから裁定に上げる。
4. **Oort 定数採用値**: 採用ポテンシャルから導出される A, B と整合する1組を提示
   (不整合だと G2 差分に定式化差以外が混入する — メモ2 §3 の条件を厳守)。
5. **データ検疫フィルタ仕様**: メモ2 §5 の 4 項目(WD の DR3 RV 不採用 / RUWE<1.4 /
   PM S/N・未解決連星警戒 / RV 外れ値検疫)を確定案として上げる。
   検疫自体を G3 スイートのテスト項目に含める設計を維持。

### 実装順序(裁定と並行してよい範囲)
- 裁定不要で着手可: 軌道積分エンジンの骨格(ポテンシャルは差替可能に実装するため
  2種のどちらが主でも影響しない)、エピサイクル解析経路の骨格(**数値経路と
  コードベース非共有**の規律を最初から守ること)、G3 テストスイートの枠組み、
  s_floor=0.05 への変更とコンフィグ化、HEALPix 斑状注入ケースの実装。
- 裁定後に着手: G3 合格帯の数値固定、個別ホライズンの本実装、検疫フィルタの本適用。
