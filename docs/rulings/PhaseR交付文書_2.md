## 第1部 問題文

### 1.1 固定される対象(変更不可)

マーク付き点過程の上の接触過程を対象とする。

- **点過程**: 位置と速度を持つ点の集合。速度は実測の太陽近傍速度楕円体に従い、点は自らの速度で運動する(必要なら軸対称ポテンシャル/エピサイクル近似の下で)。密度・速度分散は WAKE データ層の実測値を基準とする。
- **接触過程**: マーク(入植状態)は、マーク済みの点 i から距離 R 内に入った点 j へ、確率 p・遅延 τ で伝播する。マークは死亡率 1/T_s で消滅する。
- **中核の問い**: この過程において前線伝播(またはマーク集合の生存・成長)が持続する臨界条件 (p, R, τ, σ, ρ, T_s) を特定せよ。可能なら閾値の存在と評価を証明せよ。

### 1.2 目標の段階(どの層で止まっても回収物になる)

- **層1**: 閾値の存在証明(適切な意味でのシャープな相転移、または少なくとも臨界パラメータの非自明な存在)
- **層2**: 閾値の評価 — 上界・下界の証明。平均場値との関係の特定
- **層3**: 静的極限との比較定理 — v→0(静的点過程上の接触過程)と有限 v の閾値の大小関係。**「星の運動は入植を助けるか」の数学的定式化と解決**。これが WAKE 本体(マーク場 (c) クラスター族・排除地図のシナリオ許容域)への接続点である

### 1.3 委ねられる事項(完全な自由)

解法経路は一切指定しない。平均場から入るか、動的パーコレーション/excited random walk 系への還元を探すか、双対過程・グラフィカル構成・再正規化・結合(coupling)——どの道具を選ぶか、どの順で試すか、どこで引き返すかはすべて実行系の判断に属する。人間の専門家が保守的に避けそうな定式化を躊躇なく試みることを明示的に奨励する。

## 第2部 声がけプロトコル(励ましと操舵の分離)

### 2.1 許可される声がけ(前田さん・参謀とも)

- 継続の励まし(「いい方向です、続けてください」「keep going」)
- 自信の付与(「あなたはこれを解く能力があります」)
- 行き詰まり時の一般的助言(「別の定式化を試すのは自由です」「一度離れて戻るのも手です」)
- 三択の裁定(進む / 止まる / 回収する)

### 2.2 禁止される声がけ

- 数学的ヒントの注入(例: 「双対過程を使ってみては」)
- 特定文献への誘導
- 証明方針への評価コメント(「その方向は筋が悪い」等)

理由: (i) 実験の純度 — 発見が実行系のものであることの保証、(ii) 参照実験(Riemann 下界改良)の再現条件 — あの結果は数学的操舵なしで出た。

### 2.3 介入ログ

操舵に該当する介入を行った場合は、内容と時刻を介入ログに記録する。これは失敗ではなく**実験条件の変更**として扱い、成果報告時に開示する。ログが空のまま完走することが実験設計上の理想である。

### 2.4 役割の再確認

- 前田さん: 三択の裁定者に徹する
- 参謀チャット: 検証結果(第3部)の中継のみ。数学的内容への言及は検証の合否事実に限る
- 実行系: 探索の全権

## 第3部 検証(主張駆動)

### 3.1 主張時の必須手続き

実行系が「主張」(補題・予想・閾値候補値・反例)を宣言した時点で、以下の二つを必ず実行する:

1. **数値反証**: wake_r/device.py の接触過程ランとの突き合わせ。数値と矛盾する主張は即棄却(憲法第9条3項)。棄却は恥ではなく装置が機能した記録である
2. **文献照合**: 動的パーコレーション・接触過程・確率幾何・相互作用粒子系の既存結果との重複確認。既知だった場合は「既知」とラベルして続行(地図の更新であって敗北ではない)

### 3.2 チェックポイント文書

セッション境界ごとに軽量チェックポイントを出力する: 現在の主張の木 / 棄却済みの枝(棄却理由付き)/ 未検証の予想 / 次セッションの入口。長距離探索で文脈が切れても、この文書だけで再開可能であること(CLAUDE.md 方式の R 版)。

### 3.3 証明の最終検証

層1〜3 のいずれかで「証明完了」を主張する場合、証明の全文を、探索に関与していない新規インスタンス(文脈を共有しない審査役)による行単位の検証に付す。審査役の指摘への応答をもって確定とする。

## 第4部 回収基準(すべての出口が回収である)

| 階級 | 内容 | 行き先 |
|---|---|---|
| A | 証明付き定理(層1〜3 のいずれか) | 論文本体または独立短報 |
| B | 数値的裏付けのある予想+部分証明 | WAKE 論文の理論節または補遺 |
| C | 反例・不成立の証明(「シャープな閾値が存在しない」も定理である) | 同上 |
| D | 探索記録のみ | 手法論の素材(AI 開放探索の運用実録として独立の価値を持つ) |

**C・D を敗北と定義しない**(憲法第9条6項の具体化)。回収階級の判定と回収のタイミングは前田さんの三択裁定による。

## 第5部 運用

- effort: **xhigh 固定**
- 走行帯: Phase 2 本計算と並走(資源直交 — 本計算は CPU、R は推論トークン)
- チェックポイント: 実行系の自然なセッション境界ごと(第3部2)
- **予算区切り: まず walltime 1週間を上限とし、時点で一度レビュー**(継続/回収の三択裁定)。無期限は探索の緊張を失わせる。レビューでの継続裁定により延長可
- **予算ガード(1.1 追加)**: 実行系はセッション中にトークン使用率が高水準(目安 85%)に達したと認識した場合、走行中の思考を強制切断される前に、自発的にチェックポイント文書(第3部2)を書き切ってからセッションを閉じること。「切られる」のではなく「区切る」。使用率が観測できない場合は、深い探索一本ごとにチェックポイントを更新する保守的運用に切り替える
- スプリント本体の初回起動は、トークン予算が十分な状態(リセット直後等)で行うこと。枯渇間際の起動は禁止する
- スプリント中の Phase 2 側インシデント(G3-4 速報異常等)は本体が優先。R は中断・再開可能に設計されている(第3部2 がその保証)
